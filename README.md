# lostcoords-ui

A Rails engine with the UI primitives Lost Coordinates apps share. It ships class builders as view helpers,
a few partials, Stimulus controllers and their helper modules, and the Tailwind v4 stylesheets they rely on.
Runtime stays on Propshaft and importmap; there is no JavaScript build step.

## Install

```ruby
gem "lostcoords-ui", github: "lostcoords/ui"
```

The engine adds its helpers to every host view, its JavaScript to the asset paths and its pins to the
importmap. Partials render as `lostcoords/ui/components/<name>`. Translations live under `lostcoords.ui.*`.

### Stylesheet

Import the gem's entry from the host's Tailwind input, after the host's tokens:

```css
@layer theme, base, layout, components, modules, utilities;

@import "tailwindcss/theme.css" layer(theme);
@import "tailwindcss/preflight.css" layer(base);
@import "tailwindcss/utilities.css" layer(utilities);

@custom-variant dark (&:where(html[data-theme="dark"], html[data-theme="dark"] *));

/* tokens */

@import "../builds/tailwind/lostcoords_ui.css";
```

Tailwind resolves `@import` by path, and Bundler decides where the gem lives. tailwindcss-rails' `tailwindcss:engines`
task, which runs before every `tailwindcss:build` and `tailwindcss:watch` (and so before `assets:precompile`), writes
`app/assets/builds/tailwind/lostcoords_ui.css` with the absolute path to the gem's
`app/assets/tailwind/lostcoords_ui/engine.css`. `app/assets/builds` is already ignored by a Rails app's `.gitignore`
and `.dockerignore`, so there is nothing to commit. The file does not exist until the first Tailwind build, so a lint
that checks imports should skip it.

The gem's stylesheets write into the `components` and `modules` layers, so the host declares that layer order.
The builders use a `dark:` variant, which the host defines. `ui.css` carries its own `@source` lines, so Tailwind
scans the gem's helpers, views and JavaScript wherever the gem is installed.

### Tokens

The gem ships no theme. Its CSS and JS read the custom properties in `Lostcoords::Ui::TOKENS` and the host
defines every one. Check a host stylesheet with:

```sh
bin/rails "lostcoords:ui:tokens:check[app/assets/tailwind/tokens.css]"
```

`lostcoords:ui:tokens:generate[path]` rebuilds the list from what the compiled CSS and JS actually read.
`test/dummy/app/assets/tailwind/application.css` is a complete reference host.

### Importmap

The engine pins its modules under the host's own keys, `controllers/*` and `helpers/*`, so
`eagerLoadControllersFrom("controllers", application)` registers the gem's controllers with no extra wiring.
A host file with the same name, such as `app/javascript/controllers/sheet_controller.js`, shadows the gem's.

## Docs

The docs at https://ui.lostcoords.com are a Rails ERB app in `test/dummy`. Each component
page renders the gem's helpers and partials alongside the ERB that produced the example.
API signatures come from the helper definitions. `bin/house-rules` requires an example
for every public builder.

Run `parcela up --detach` and open https://ui.localhost. Parcela starts Rails and the
Tailwind watcher. `parcela down` stops this environment.

`bin/rails lostcoords:ui:showcase` exports the home, component pages, token reference and
assets to `docs/` for GitHub Pages. CI checks that this export matches the source.

## Development

```sh
bundle install && npm ci
bin/rails server            # the dummy app in test/dummy
bin/rails tailwindcss:build
bin/test
bin/lint
```
